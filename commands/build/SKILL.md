## Lean path — the start prints `Mode: lean`: this section is the whole run
1. **One call:** `python ${CLAUDE_PLUGIN_ROOT}/tools/status.py next --phase build --ticket <id>` — no id named: leave `--ticket` out and the start picks the seat's next startable ticket (the user named a seat: add `--seat <seat>`). Open no rule file.
2. On the ticket branch (the start names it), **implement the ticket and its tests**; the ticket's DoD is the DoD. A new file in one write; every edit to a file in one message.
3. **While coding, only the start's `Per edit` commands** — the ticket's tests, and format + lint once, just before the commit; the full project check runs ONCE, at step 5. Commit locally. **Every hook on:** never set `SKIP`, never `--no-verify` / `-n`; a failing hook is fixed, never skipped; truly blocked: STOP and tell the user which check fails and why.
4. **Reviews, both at once, by the start's `Reviewer:` line:** ONE helper with a fresh context (it did not write the code) reviews the ticket's commits while you run the code review the line names (a tool with no review command: the helper does both, `CAPABILITIES.md` §Code review); no helper on your tool: the line says what instead (a NEW chat reviews it; the chat that wrote the code is never its own reviewer — its review is recorded `not independently reviewed`, a gap said in the close) — and ask: what REAL thing could this code touch by mistake (a real shop, account, inbox, payment, user)? Fix every real finding, commit. Then ONE question: review again, over the fixes' files only (recommended after a HIGH/MEDIUM)? No skips it; no round 3.
5. **`docs/features/<feature>.md` in ONE write** (`${CLAUDE_PLUGIN_ROOT}/templates/feature-doc.md`): `## 1.` In short · `2.` What you can do now · `3.` What it protects you from · `4.` Not done yet, plain words and short sentences for the owner; after `---`, `## 5.` For developers and coding agents: how verified · `Real-world reach: <what> - guarded by test_<name>` · `### 5.4 Review`: findings (severity · file:line · what goes wrong · fixed by) or CLEAN · why each changed file the ticket did not list changed. **Every new setting in the runbook/README too**, and any `STRUCTURE.md` line — then **`gate.py --ticket <id> --close` once**, over it all (it also fails when the full suite never runs the ticket's test files — fix the line it names: the recipe, CI or `testpaths`); commit.
6. **Record:** `status.py ticket <id> --dod yes|partial --verified "<command> → <result>" --doc docs/features/<feature>.md --review "<route>: code + security review R1 <n> findings · R2 (<n> files) <n> findings"` (route: `helper agent` · `review command` · `new chat` · `another tool` · `not independently reviewed`) (or `· R2 skipped by the user: <reason>`); LOW findings left unfixed → ONE grouped issue (`gh issue create`), its number in `--low "#<n>"`, or `--low "not filed: <why>"`. It moves the card to In Review — say every line it prints. Then the close `next` printed.
